# Итерация 001 — базовый helpdesk

Дата: 2026-09-18

## Цель

Собрать API-first helpdesk с нуля: единый инбокс для WhatsApp, VK и Email, ответы операторов, метрики поддержки. Фронтенд — отдельный клиент API.

## Что сделано

**Ядро**
- `backend/app/models.py` — Workspace, User, Channel, Contact, Conversation, Message, Event, WebhookLog
- `backend/app/database.py` — SQLAlchemy, сначала SQLite с WAL
- `backend/app/security.py` — bcrypt, JWT, зависимости FastAPI
- `backend/app/schemas.py` — Pydantic-схемы, они же Swagger

**Роутеры**
- `backend/app/routers/{auth,users,channels,contacts}.py`
- `backend/app/routers/conversations.py` — инбокс, ответы, статусы, таймлайн
- `backend/app/routers/metrics.py` — сводка, операторы, каналы, динамика
- `backend/app/routers/webhooks.py` — приём от WhatsApp, VK Callback, Email-моста

**Сервисы**
- `backend/app/services/ingest.py` — нормализация трафика, расчёт FRT
- `backend/app/services/metrics.py` — метрики с диалект-агностичным SQL
- `backend/app/services/pollers.py` — IMAP-поллер, VK Long Poll

**Каналы** — адаптеры исходящих в `backend/app/channels/{whatsapp,vk,email}.py`

**Фронтенд** — `frontend/index.html`, `frontend/styles.css`, `frontend/app.js`: инбокс трёхпанельный, метрики, каналы, команда

## Проверено

- Холодный старт с пустой базой, сид админа и демо-данных
- Логин, `/auth/me`, отказ при неверном пароле
- Инбокс с фильтрами по статусу, каналу, ответственному, поиску
- Вебхуки WhatsApp в трёх форматах, идемпотентность по `external_id`
- Ответ оператора: при недоступном провайдере сохраняется со `status=failed`
- Переоткрытие `resolved` → `open` с ростом `reopen_count`
- Метрики: FRT, ART, SLA, бэклог, срезы по операторам и каналам

## Найдено и исправлено в процессе

- **Вход не работал вообще** — `EmailStr` отвергает домен `.local`, `admin@helpdesk.local` получал `422`. Заменено своим валидатором `_check_email`
- **Отрицательное время решения** — диалог создавался с `created_at = utcnow()` (момент записи), а закрывался по времени сообщения. Исправлено: `created_at` от первого входящего
- **Молчаливый игнор `mark_status`** — при недоступном провайдере статус не применялся без всякого уведомления. Добавлены `status_applied` и `notice`
- **Логика «не отправлять тесты клиентам» нарушена** — smoke-тест отправил сообщение живому клиенту. Отозвано через `messages.delete`, добавлен `dry_run`
