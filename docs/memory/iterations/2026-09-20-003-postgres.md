# Итерация 003 — переезд на PostgreSQL

Дата: 2026-09-20

## Цель

Уйти с SQLite перед внедрением мультитенанта: при нескольких поллерах и вебхуках он блокирует всю базу на каждой записи.

## Что сделано

- Контейнер `helpdesk-postgres` (`postgres:16-alpine`), порт `127.0.0.1:18401`, лимит памяти 256 МБ, том `helpdesk_pgdata`, `restart: unless-stopped`
- Наружу не опубликован — доступен только с сервера
- Драйвер `psycopg`, схема `postgresql+psycopg://`
- Данные перенесены скриптом: пользователи, каналы, контакты, 63 диалога, 4535 сообщений, события
- Последовательности id выровнены через `setval`, иначе новые записи конфликтовали бы
- SQLite сохранён как `data/helpdesk.db.sqlite-backup` на случай отката

## Проверено

- Импорт приложения, старт сервиса, данные на месте
- Все 13 ручек API отвечают `200`
- Поллер VK работает, соединение живое
- Контейнер потребляет ~20 МБ, наружу закрыт

## Найдено и исправлено

**`500` практически на всех ручках после переезда.** Причина: SQLite-специфичные функции, которых в Postgres нет:
- `func.strftime` — форматирование дат
- `func.julianday` — разница между датами
- `func.printf` — форматирование чисел

Исправлено:
- `_last_messages` переписан с `max(id)` на оконную функцию `row_number() over (partition by ... order by ...)` — работает в обеих базах
- В `backend/app/services/metrics.py` добавлены хелперы `_duration_seconds` и `_bucket_expr` с ветвлением по `db.get_bind().dialect.name`

Вывод: SQL в проекте обязан быть портируемым, см. ADR-003.
