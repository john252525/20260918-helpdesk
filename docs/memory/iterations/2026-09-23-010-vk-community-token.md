# Итерация 010 — VK OAuth на community-токен и резолв коротких имён

Дата: 2026-09-23

## Цель

Довести флоу подключения группы ВК до рабочего состояния на реальном
приложении и убрать ручной ввод ID группы.

## Что сделано

- `backend/app/services/vk_oauth.py`: переход на community Authorization Code
  Flow (обязательный `group_ids`), разбор ссылок и резолв коротких имён.
- `backend/app/routers/vk_oauth.py`: остались `start` и `callback`; callback
  сам сохраняет канал через общий `save_vk_channel`.
- Удалены эндпоинты `groups` и `connect` и модалка выбора сообщества: они
  опирались на `groups.get`, недоступный этому приложению.
- `frontend/app.js`: поле «Ссылка на группу ВК» вместо выбора из списка.
- `backend/.env`, `backend/.env.example`, `backend/app/config.py`: настройки
  приложения, секрет, сервисный ключ.

## Почему переделано с итерации 009

Приложение VK ID умеет только community-flow: `scope=manage` без `group_ids`
даёт `Security Error`, а право `groups` (нужно для списка сообществ) VK выдаёт
по заявке в поддержку. Зато community-flow сразу отдаёт токен сообщества —
ровно тот, что нужен адаптеру. Подробности — ADR-022.

## Проверено

- `start` формирует URL с `client_id`, `group_ids`, `scope=manage,messages`,
  `state`; принимает `vk.com/club123`, короткое имя, число, `-число`,
  `m.vk.com/...`; мусор и неизвестная группа — понятная ошибка.
- `callback`: отказ, битый/пропущенный/повторный `state` — тексты в SPA.
- Сквозной тест с подменённым обменом: канал создаётся, Long Poll включён,
  `state` одноразовый.
- Ручной флоу не тронут.
- Позже выяснилось ограничение на отправку — итерация 011.

## Заметки / дальше

- Отправка требует отдельного ключа группы (итерация 011, ADR-023).
- Резолв коротких имён: `utils.resolveScreenName` для сервисного токена
  недоступен (ошибка 1051), используется `groups.getById`.
