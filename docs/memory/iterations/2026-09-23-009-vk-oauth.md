# Итерация 009 — подключение группы ВК через OAuth

Дата: 2026-09-23

## Цель

Добавить новый флоу подключения группы ВК через VK OAuth (Authorization Code
Flow), сохранив ручной ввод токена как резервный. Оба флоу сходятся в один
путь сохранения, чтобы дальше код не различал источник токена.

## Что сделано

- `backend/app/config.py`: настройки OAuth (`vk_app_id`, `vk_client_secret`,
  `vk_oauth_redirect_uri`, `vk_oauth_frontend_url`).
- `backend/app/services/vk_oauth.py`: сборка authorize-URL, подписанный `state`
  с одноразовым `jti`, обмен `code` на токен, `groups.get` (группы, где юзер
  админ), проверка прав `check_group_rights`, короткоживущие тикеты.
- `backend/app/services/vk_connect.py`: единый путь сохранения VK-канала для
  обоих флоу (`save_vk_channel`), включение Long Poll и уникализация имени
  переехали сюда из роутера.
- `backend/app/routers/vk_oauth.py`: `start`, `callback`, `groups`, `connect`.
- `backend/app/routers/channels.py`: ручной флоу делегирует сохранение в
  `save_vk_channel`; поведение и тексты не изменились.
- `backend/app/main.py`: роутер `vk_oauth` подключён перед `channels`.
- `backend/app/schemas.py`: схема `VKOAuthConnect`.
- `frontend/app.js`: кнопка «Подключить через ВК», обработка возврата из VK,
  модалка выбора сообщества, откат к ручной форме при нехватке прав.
- `frontend/styles.css`: блок кнопки и список сообществ.
- `backend/.env`, `backend/.env.example`: секрет и `redirect_uri`.

## Ключевое решение

OAuth выдаёт **пользовательский** токен, а для приёма сообщений обычно нужен
**токен сообщества**, который через OAuth не выдаётся. Поэтому флоу гибридный:
OAuth выбирает группу, а если VK отвечает «нужен ключ группы» (коды 15/27),
канал не создаётся молча — форма ручного ввода открывается с уже подставленным
ID группы. См. ADR-021.

## Проверено

- `start` формирует URL со всеми параметрами (`client_id`, `redirect_uri`,
  `scope=manage,messages,offline`, `response_type=code`, `state`, `v=5.199`).
- Без токена — `401`.
- `callback`: отказ (`access_denied`), битый `state`, отсутствие `state`,
  отсутствие `code`, повторное использование `state` — все ведут в SPA с
  понятным текстом, кода нет в URL.
- Обмен недействительного `code` с реальным VK — «Code is invalid or expired».
- `groups` и `connect` с чужим/просроченным тикетом — `400`.
- Сквозной `connect` на тестовой группе — `201`, канал создан, Long Poll включён,
  тикет одноразовый.
- Кросс-групповой токен распознаётся как «нужен ключ группы» (откат к ручной форме).
- Ручной флоу: `validate` валидным токеном — `ok`; дубль имени — `409`; пустые
  поля — понятная ошибка. Поведение не изменилось.
