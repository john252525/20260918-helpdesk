# Итерация 006 — управление из UI, устойчивость Long Poll

Дата: 2026-09-21

## Цель

Вывести в интерфейс всё, что доступно только через API. Закрыть потерю сообщений при перезапуске.

## Что сделано

**Устойчивость Long Poll**
- Курсор `ts` сохраняется в `Channel.config.long_poll_ts` после каждого опроса, читается при старте
- Супервайзер при запуске поллера подхватывает сохранённый курсор, а не берёт свежий у VK

**Удаление через интерфейс**
- Компания — кнопка на карточке, подтверждение вводом кода компании. На бэке проверка `confirm`, поэтому случайный запрос не сработает
- Канал — кнопка, при наличии переписки первый отказ `409` с объяснением, потом подтверждение «удалить вместе с историей»
- Сотрудник — кнопка в списке компании

**Прочее в UI**
- Смена пароля — клик по аватару, требует текущий пароль
- Правка данных клиента — клик по имени в шапке диалога
- Журнал вебхуков — кнопка на странице каналов

**Фронтенд**
- Исправлена вспышка формы входа при обновлении страницы. Причина: форма была видима по умолчанию, а скрывалась только после проверки токена в JS. Теперь оба экрана скрыты, показывается сплэш до завершения проверки, плюс таймаут-страховка на случай если `frontend/app.js` не загрузится

## Проверено

- **Курсор выживает перезапуск:** `ts=23` до `systemctl restart`, `ts=23` после. Раньше начинал с нуля и терял всё за время простоя
- Канал с историей → `409`, пустой → `204`
- Компания без верного `confirm` → `400`, не-суперадмин → `403`
- Смена пароля: неверный текущий → `400`, тот же самый → `400`, успешная смена и последующий вход новым
- Правка клиента, чужой контакт → `404`
- Журнал вебхуков без токена → `401`

## Найдено и исправлено

- **Сервис упал.** В `backend/app/routers/channels.py` использован `Query`, но не импортирован. Приложение не стартовало
- **Интерфейс не парсился.** Лишняя закрывающая скобка в `frontend/app.js` при вставке кнопки удаления
- Обе поломки — от того, что проверка шла после правки, а не сразу. Правило зафиксировано в `docs/memory/CONVENTIONS.md`
