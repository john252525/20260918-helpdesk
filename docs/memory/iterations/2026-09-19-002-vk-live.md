# Итерация 002 — подключение живого VK

Дата: 2026-09-19

## Цель

Подключить реальную группу VK, импортировать историю, проверить приём и отправку на живых данных.

## Что сделано

**Настройка группы**
- Включён Long Poll через `groups.setLongPollSettings` с `enabled=1` и `message_new=1`. Важно: `enabled` — отдельный параметр от флагов событий, без него VK принимает запрос, но приём остаётся выключенным
- Токен и ID группы прописаны в канал через API

**Импорт истории**
- Загружены диалоги за 30 дней, ~63 обращения
- Импортированы и входящие, и **исходящие** сообщения — сначала я загрузил только входящие, из-за чего все диалоги выглядели неотвеченными, а метрики врали. Исправлено добавлением `author_type` в `record_outbound`

**Отображение**
- Импортированные ответы показывались как «System» вместо «Оператор». Исправлено в `backend/app/routers/conversations.py`
- Демо-данные удалены, вместе с ними тестовые операторы и каналы
- `backend/app/seed.py` исправлен: перестал пересоздавать удалённые сущности при каждом рестарте

## Проверено

- Входящее сообщение из группы появляется в инбоксе
- Ответ из интерфейса доходит до клиента (сверено через VK API)
- FRT считается, метрики не отрицательные
- Хронология сообщений в диалоге корректна

## Найдено и исправлено

- **Хронология — все входящие подряд, затем все исходящие.** При импорте ответы получили большие `id`, хотя по времени были раньше. Сортировка переведена на составной ключ `(created_at, id)` в `backend/app/routers/conversations.py`
- **Превью последнего сообщения врало** — `_last_messages` брал `max(Message.id)`. Та же причина, тот же фикс
- **Утечка VK-токена в логи** — `httpx` печатает URL на INFO, а токен передавался в query-параметрах. Вызовы переведены на `POST`, логгеры приглушены, старые логи уничтожены через `shred`
