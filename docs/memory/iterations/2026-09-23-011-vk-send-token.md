# Итерация 011 — ключ группы для ответов на OAuth-канале

Дата: 2026-09-23

## Цель

Вернуть отправку сообщений для группы, подключённой через VK OAuth: приём
работал, ответы из интерфейса — нет.

## Что сделано

- `backend/app/channels/vk.py`: адаптер предпочитает `config.send_token`,
  иначе берёт `config.access_token` (ручной флоу не затронут).
- `backend/app/routers/vk_oauth.py`: при подключении проверяется
  `can_use_messages`; при неудаче в callback уходит `warn`, а в конфиг —
  `needs_send_token`. Добавлен `POST /channels/vk/oauth/send-token`.
- `backend/app/schemas.py`: схема `VKSendToken`.
- `frontend/app.js`: после возврата из VK показывается шаг «Ключ для ответов»;
  на карточке канала, которому не хватает ключа, — кнопка «Добавить ключ».
- `frontend/styles.css`: строка предупреждения.

## Почему так

Community-токен из VK ID принимает входящие (Long Poll), но VK отклоняет его
на всех `messages.*` ошибкой 1051, хотя права `messages`+`manage` есть. Ключ
группы из настроек сообщества на тех же методах работает. Подробности и
замеры — ADR-023.

## Проверено

- `can_use_messages`: OAuth-токен — False, ключ группы — True.
- `send-token`: неверный ключ — 400, чужой канал — 404, пустой — 422,
  рабочий ключ — 200 и `needs_send_token: false`.
- Адаптер после привязки берёт `send_token`; без него — `access_token`.
- Входящие на OAuth-канале по-прежнему идут (Long Poll).
- Ручной флоу не менялся.
- Импорт бэкенда, синтаксис фронта, слой памяти — зелёные.

## Заметки / дальше

- Написать в `devsupport@corp.vk.com` про 1051 на community-токенах VK ID.
- Если VK исправит поведение — поле `send_token` просто перестанет
  заполняться, код менять не придётся.
- В ходе диагностики в живой группе было отправлено два тестовых сообщения;
  оба удалены. Правило «не писать в живые каналы» нарушено — впредь проверки
  только на заведомо несуществующих получателях.
