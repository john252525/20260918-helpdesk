# Итерация 004 — мультитенант и роли

Дата: 2026-09-20

## Цель

Разделить платформу на компании: у каждой свои сотрудники, каналы и диалоги. Роли вместо одного флага администратора.

## Что сделано

**Модели**
- Таблица `workspaces` (slug, name, is_active)
- `workspace_id` добавлен в `users`, `channels`, `contacts`, `conversations`
- `users.role` — `superadmin`, `admin`, `agent`
- `channels.webhook_secret` — токен для URL вебхука

**Миграция на живой базе**
- `Base.metadata.create_all` создаёт только новые таблицы, поэтому колонки в существующих добавлены явными `ALTER TABLE`
- Сняты глобальные unique-констрейнты, поставлены с `workspace_id` в составе ключа: иначе два клиента с одним номером в разных компаниях конфликтовали
- Существующие данные привязаны к первой компании `whatsapi`, `admin@helpdesk.local` повышен до суперадмина

**Изоляция**
- Хелпер `_scoped_conversation(db, id, user)` в `backend/app/routers/conversations.py` — отдаёт `404` при чужой
- Фильтрация во всех роутерах: `conversations`, `contacts`, `channels`, `metrics`
- В метриках счётчики сообщений фильтруются через `JOIN` с диалогом: у сообщения нет своего `workspace_id`
- Суперадмин видит всё, остальные получают `-1` при отсутствии компании — пустой результат лучше утечки

**Роли**
- `backend/app/security.py` — `require_admin`, `require_superadmin`, `effective_workspace`
- Только суперадмин может создать компанию или другого суперадмина
- JWT несёт `role` и `wid`

## Проверено

Создана вторая компания, проверено 19 сценариев:
- Не видит диалоги первой ни в списке, ни по прямому id, ни через поиск
- Не читает сообщения и события, не меняет статус
- Не видит каналы, не может их выключить, не получает webhook
- Метрики пустые
- Оператор второй компании тоже ничего не видит
- Суперадмин видит обе

## Найдено и исправлено

- **Сервис упал при добавлении ролей.** `require_admin` объявлен перед `get_current_user`, а использует его в аргументе по умолчанию — Python вычисляет их в момент определения функции. `NameError` при импорте. Хелперы перенесены ниже
- **`500` на чтении сообщений.** При изоляции я заменил `conv = db.get(Conversation, id)` на `_scoped_conversation(...)` **не присвоив результат**, а ниже код использует `conv.contact`. Исправлено
