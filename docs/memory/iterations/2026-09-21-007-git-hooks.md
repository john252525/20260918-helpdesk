# Итерация 007 — git-хуки и автоматическая проверка памяти

Дата: 2026-09-21

## Цель

Сделать обновление слоя памяти **механическим**, а не добровольным. Сейчас правило «после итерации обнови STATE.md» записано в `AGENTS.md`, но держится на дисциплине исполнителя. Через несколько сессий его перестанут соблюдать.

## Что сделано

**Инициализация репозитория**
- `git init` в корне проекта
- `.gitignore` расширен: исключены `.venv/`, `__pycache__/`, `data/`, `backend/.env`, `*.log`. Секреты и данные клиентов в репозиторий не попадают

**`scripts/pre_commit.py`** — сами проверки. Четыре блока:
1. `check_docs.py` — слой памяти целиком
2. Импорт `backend.app.main` — ловит ошибки, из-за которых сервис не стартует
3. `node --check frontend/app.js` — ловит синтаксис, из-за которого интерфейс мёртв
4. Сверка: если менялся код в `backend/app/` или `frontend/`, но `STATE.md` не тронут — предупреждение

**`scripts/install_hooks.py`** — установка хуков одной командой. Папка `.git/hooks/` не попадает в репозиторий, поэтому на каждой машине установку надо делать отдельно. Скрипт идемпотентен.

**`.git/hooks/pre-commit`** — тонкая обёртка, вызывает `pre_commit.py`.

## Важные решения

**Проверка `STATE.md` — предупреждение, не блокировка.** Соблазн был сделать жёстко: нет правки в STATE — нет коммита. Отвергнуто: иногда коммитят правку, которая не меняет состояние проекта (опечатка в комментарии, форматирование). Жёсткий запрет вызовет раздражение и привычку коммитить с `--no-verify` — то есть проверка перестанет работать вообще.

**Обход задокументирован.** `git commit --no-verify` упомянут в самом скрипте, в сообщении об ошибке и в `CONVENTIONS.md`. Если хук мешает по делу — это законный путь, а не «хаканье». Иначе следующий агент будет страдать, не понимая, как отключить.

**Проверяются staged-файлы, а не рабочая копия.** Иначе хук ругался бы на чужие незакоммиченные правки.

## Проверено

- **Тест 1:** коммит с изменённым кодом без правки `STATE.md` — предупреждение выведено, коммит прошёл
- **Тест 2:** в `main.py` добавлен несуществующий импорт — коммит **заблокирован**, в выводе трейсбек
- **Тест 3:** после отката импорт восстанавливается, проверки проходят
- Идемпотентность установщика: повторный запуск перезаписывает хуки без ошибок

## Спотыкание в процессе

**Heredoc с тройными кавычками рвётся.** Попытка передать Python-скрипт через
`python - <<'PYEOF'`, когда внутри есть `'''...'''`, привела к ошибке
`unterminated triple-quoted string literal` — оболочка не нашла закрывающий
маркер. Следом упало и многострочное сообщение коммита через `-m`.

**Как делать правильно.** Скрипты, меняющие документы, записывать в файл
через `cat > /tmp/script.py <<'SCRIPT_END'` (маркер не должен встречаться
в содержимом), затем запускать. Сообщение коммита — в файл и `git commit -F`.

Это тот же класс ошибки, что уже ловился раньше: правка через инструмент,
который молча ломается на сложном содержимом.
