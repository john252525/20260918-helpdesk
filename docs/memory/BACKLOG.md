# Отложенное и техдолг

Что сознательно не сделано или отложено. **Не «чинить» без явного запроса** — решения принимались осознанно.

## Инфраструктура

**Callback API как альтернатива Long Poll.** Переключатель на канал. Нужен при росте больше 10–15 компаний: сейчас поток на каждый канал, плюс VK ограничивает число одновременных подключений к одной группе. Каркас в `backend/app/routers/webhooks.py` написан. До этого момента Long Poll с сохранённым курсором рабочий вариант.

**Alembic для миграций.** Сейчас схема меняется вручную через `ALTER TABLE`. Для проекта с одной базой это терпимо, при росте — нужен нормальный инструмент версионирования.

**Вынос токенов из БД.** Креды каналов лежат в `Channel.config` открытым текстом. Осознанный выбор ради самодостаточности канала: подключаемый канал несёт всё нужное с собой. При ужесточении требований — переменные окружения или шифрование.

**Дашборд для суперадмина.** Список компаний есть, но без цифр: сколько у каждой диалогов, каналов, сотрудников, какой SLA. Сейчас видно только название и код.

**Хук `commit-msg`.** Сейчас проверяется содержимое коммита, но не сообщение. Можно требовать формат с номером итерации. Отложено: формат сообщений ещё не устоялся.

**Поиск секретов в staged-файлах.** Хук проверяет ссылки и синтаксис, но не ищет VK-токены, пароли и приватные ключи в закоммичиваемых файлах. `.gitignore` исключает `.env` и `data/`, но случайно вставленный в код токен пройдёт. Можно добавить regex-скан содержимого staged-файлов.

**CI как вторая линия.** Локальный хук обходится через `--no-verify`. При появлении нескольких разработчиков стоит добавить CI. См. ADR-012.

## Продукт

**Auto-reply искажает FRT.** Автоответчик группы срабатывает за секунды и засчитывается как первый ответ оператора. Метрика занижается. Решение: исключать сообщения с точным текстом автоответа из расчёта. **Требуется точный список текстов от заказчика** — эвристика по времени проверена и оказалась ошибочной, под неё попадают живые операторы.

**Автозакрытие старых диалогов.** В VK нет понятия «закрыть обращение», поэтому диалоги висят в `open` даже когда клиент написал «спасибо». Бэклог раздут. Решение: закрывать автоматически там, где последним писал оператор и прошло больше N дней.

**Файловое хранилище вложений.** Сейчас `attachments` в сообщении — только метаданные, файлы не хранятся. Для полноценной работы нужен S3 или локальное хранилище.

**Уведомления и SLA-эскалации.** Нет оповещений о новых обращениях, нет эскалации при приближении к нарушению SLA. Оператор узнаёт о новом диалоге только зайдя в интерфейс.

**Поиск по всей истории.** Есть фильтр по тексту в пределах инбокса, но нет полнотекстового поиска по всей базе.

**Экспорт диалогов.** Нет выгрузки переписки в файл — иногда требуется для отчётности.

## Интерфейс

**Редактирование канала.** Из UI только вкл/выкл. Поменять имя или креды — нельзя. Нужен, если у компании сменился токен VK.

**Создание диалога первым исходящим.** Ручка `POST /conversations` работает, кнопки в интерфейсе нет. Полезно, когда оператор хочет написать клиенту первым.

**Массовые операции.** Нет выбора нескольких диалогов и группового действия — закрыть, назначить, сменить приоритет.

**Роли с правами по операциям.** Сейчас три роли (`superadmin`, `admin`, `agent`). Может понадобиться детальнее: например, оператор видит только свои диалоги, или супервизор может читать чужие.

## Известные ограничения, не баги

**WhatsApp и Email не проверены на живом провайдере.** Креденшелов не было. Логика отправки и приёма написана, вебхуки защищены секретом, но сквозной сценарий на реальном провайдере не проходил.

**Пароль `probnik12345` слабый.** Ставился для отладки тестовой компании. Сменить перед реальной работой — через интерфейс, клик по аватару.

**Импортированная история VK без привязки к операторам.** В VK не видно, кто из операторов отвечал — все ответы идут от имени группы. Поэтому в метриках по операторам импортированные данные не учитываются. Появится, когда операторы начнут отвечать из интерфейса.
