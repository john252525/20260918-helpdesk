# Соглашения проекта

## Проверка перед перезапуском — обязательно

Сервис не должен падать из-за опечатки. Два прогона ловят почти всё:

```
./.venv/bin/python -c "from backend.app.main import app"
node --check frontend/app.js
```
Первый находит ошибки импорта, второй — синтаксиса. **Запускать после каждой правки, не перед самым перезапуском.** За сессию семь поломок сервиса случились из-за того, что проверка шла после.

Отдельная ловушка: **правка кода текстовой заменой**. Скрипт молча ничего не меняет, если строка не совпала байт-в-байт. Всегда проверять результат `grep`-ом сразу после.

## Python

**Стиль.** SQLAlchemy 2.0 с `Mapped[]` и `mapped_column()`. FastAPI с явными `response_model`. Полные тайп-хинты, `Optional[X]` для nullable.

**Портируемость SQL.** Проект должен работать и на SQLite, и на PostgreSQL. Запрещены `strftime`, `julianday`, `printf` — в Postgres их нет. Вместо `max(id)` для «последней записи» — оконная функция `row_number() over`. Если функция диалект-специфична, ветвить по `db.get_bind().dialect.name` через хелпер.

**Комментарии на английском.** Тексты интерфейса и сообщения API — на русском. Причина: код читают разработчики, интерфейс — операторы.

**Изоляция компаний.** Любой запрос к `conversations`, `contacts`, `channels`, `metrics` фильтруется по `workspace_id`. Для одиночной сущности — хелпер `_scoped_conversation(db, id, user)`, который отдаёт `404` при чужой. Сообщения фильтруются через `JOIN` с диалогом: у них нет своего `workspace_id`.

**Секреты в логах.** `httpx` на уровне INFO печатает полный URL — токены утекают. Все вызовы внешних API, где есть токен, идут через `POST` (токен в теле), а логгеры `httpx` и `httpcore` приглушены до `WARNING`.

## JavaScript / фронтенд

**Без фреймворков и сборки.** Vanilla JS, один файл `frontend/app.js`. Помощник `el(tag, attrs, ...children)` для создания DOM.

**Портируемость и склейка строк.** В JavaScript соседние строковые литералы **не склеиваются**, в отличие от Python. Нужен явный `+`:

```
// правильно
'первая часть ' +
'вторая часть'

// синтаксическая ошибка
'первая часть '
'вторая часть'
```
Эта ошибка один раз положила весь интерфейс.

**Мобильная вёрстка.** Паттерн master-detail: список на весь экран, переписка наезжает поверх по классу `.thread-open` на `<div id="app">`. Rail превращается в нижний таб-бар. Поля ввода `16px` — иначе iOS зумит страницу при фокусе.

**Никакой вспышки контента.** При загрузке страницы оба экрана скрыты, показывается сплэш, пока идёт проверка токена. Форма входа появляется только если токен невалиден.

**Реальные ID в примерах запрещены.** Плейсхолдеры вроде `183684222` попадают в интерфейс всем компаниям. Только безликие `123456789`.

## Тестирование

**Не писать в живые каналы.** Отправка уходит настоящему клиенту. Для проверки логики — `?dry_run=true`. Для сквозной проверки доставки — канал-заглушка с недействительными кредами.

**Smoke-тест после крупных правок.** Прогонять все основные ручки: инбокс, каналы, метрики, компании, чтение сообщений. Ошибка класса «не присвоил результат функции» не ловится импортом, только вызовом.

**Проверка изоляции.** После правок в роутерах — создать вторую компанию, убедиться что она не видит чужие диалоги, каналы, контакты ни в списке, ни по прямому id, ни через поиск, ни в метриках.

## Тесты не оставляют следов

**Тест, который пишет в боевой файл, восстанавливает его в `finally`.**
Не в конце скрипта: если прогон упадёт между записью и откатом, мусор
останется в рабочем файле и накопится при следующих запусках.

**Почему это важно.** Файл `STATE.md` однажды вырос с 48 до 308 строк:
тестовые фрагменты наслаивались, а один прогон упал до восстановления.
Заметил только при сверке размеров.

**Проверка после тестов.** Сверить `wc -l` на тронутых файлах с ожидаемым.
Если разошлось — восстановить вручную.

**Лучше — не трогать боевые файлы.** Если возможно, тест пишет в копию
во временной папке. Валидатор слоя памяти умеет принимать каталог
параметром: `--root /tmp/copy`, поэтому его тесты уже работают на копии.
См. ADR-017 и ADR-018.

**Тесты валидатора** запускаются вручную: `./.venv/bin/python
scripts/test_check_docs.py`. Прогоняются автоматически в `pre-commit`.


## Git-хуки

**Ставятся один раз на машину:**

    ./.venv/bin/python scripts/install_hooks.py

Папка `.git/hooks/` не версионируется, поэтому на новой машине хук надо
установить заново. Скрипт идемпотентен.

**Что проверяет `pre-commit`:**

| Проверка | Блокирует |
|---|---|
| `scripts/check_docs.py` — слой памяти | да |
| Импорт `backend.app.main` | да |
| `node --check frontend/app.js` | да |
| `STATE.md` обновлён, если менялся код | нет, предупреждение |

**Как обойти.** Если хук мешает по делу — например, коммитится мелкая
правка, не меняющая состояние проекта:

    git commit --no-verify -m "..."

Это законный путь, а не взлом. Жёсткая блокировка привела бы к привычке
коммитить в обход всегда, и проверка перестала бы работать.

**Где правится.** Логика — в `scripts/pre_commit.py`, установщик —
в `scripts/install_hooks.py`. После правки логики хук переустанавливать
не нужно, он вызывает скрипт каждый раз.

**Почему не CI.** См. ADR-012. Коротко: локальный хук срабатывает
мгновенно и не требует внешних сервисов.

## Правка документов и кода из скриптов

**Heredoc с вложенными тройными кавычками ломается.** Конструкция
`python - <<'PYEOF'`, внутри которой есть многострочная строка
`'''...'''`, даёт `unterminated triple-quoted string literal` —
оболочка не находит закрывающий маркер.

**Как делать:**

1. Записать Python-скрипт в файл:
   Или проще: `cat > /tmp/fix.py <<'SCRIPT_END'`, содержимое, `SCRIPT_END`
2. Запустить: `./.venv/bin/python /tmp/fix.py`
3. Удалить временный файл

Маркер (`SCRIPT_END`, `EOF`) не должен встречаться в содержимом.
Для многострочных сообщений коммита — `git commit -F /tmp/msg.txt`.

**Почему не inline.** Тот же класс проблемы, что и с текстовыми
заменами: инструмент ломается на сложном содержимом молча или
с невнятной ошибкой. Файл + запуск надёжнее и проверяемее.

**Ссылки на файлы.** Валидатор `scripts/check_docs.py` проверяет пути в
обратных кавычках. Правило простое:

| Что написано | Проверка |
|---|---|
| Полный путь со слэшем — `backend/app/routers/auth.py` | файла нет → коммит блокируется |
| Голое имя — `auth.py`, `STATE.md` | файл ищется по всему проекту; нет нигде → предупреждение |

Значит, короткие упоминания можно писать смело, а вот полный путь лучше
копировать из проекта, чтобы не ошибиться. См. ADR-015.

## Инфраструктура

**Публичный адрес — одна переменная.** `PUBLIC_BASE_URL` задаёт и URL вебхуков, и `redirect_uri` для VK OAuth. Переезд dev → prod — правка одной строки в `backend/.env`; отдельные адреса в коде не хардкодятся.

**Секреты.** Файлы с токенами — `chmod 600`. Токен в БД (`Channel.config`) — осознанное решение, но при ужесточении требований выносить в переменные окружения.

**Логи.** Только через `logging`, не `print`. Ротация настроена в `/etc/logrotate.d/helpdesk`. Токены и пароли в логи не писать.

**Миграции БД вручную.** Alembic не подключён. Новая колонка — явный `ALTER TABLE` в скрипте миграции, `create_all` добавит только новые таблицы. Unique-констрейнты для мультитенанта — с `workspace_id` в составе ключа.

**Порядок маршрутов FastAPI.** Статические пути (`/channels/validate`) объявляются **перед** динамическими (`/channels/{channel_id}`). Иначе FastAPI попытается разобрать `"validate"` как целое число.

## Запись файлов из оболочки

Heredoc с длинным телом и вложенными кавычками рвётся молча: маркер не
находится, файл остаётся пустым или обрезанным. За сессию 2026-09-21 так
пропали четыре скрипта.

**Три рабочих способа, от надёжного к простому:**

1. **Короткие фрагменты — `printf` построчно.** Не зависит от разбора
   heredoc вообще:

   ```bash
   printf '%s\n' \
   'первая строка' \
   'вторая строка' \
   > /tmp/script.py
   ```

2. **Средние скрипты — `cat` с коротким маркером.** Маркер не должен
   встречаться в содержимом:

   ```bash
   cat > /tmp/fix.py <<'ENDX'
   код
   ENDX
   ```

3. **Правки в существующих файлах — `sed` или Python-скриптом.** Для
   одного блока надёжнее, чем переписывать файл целиком.

**Обязательная проверка.** Сразу после записи — убедиться, что файл
создан и его содержимое разбирается:

   ```bash
   ls -la /tmp/script.py
   ```

Секунда проверки спасает от пяти итераций впустую.

## Порядок определений в Python

**Функция, использующая другую функцию как значение по умолчанию,
объявляется ПОСЛЕ неё.** Python вычисляет значения по умолчанию в момент
определения функции, а не вызова.

Неправильно:

```python
def require_admin(user: User = Depends(get_current_user)):  # NameError
    ...

def get_current_user(...):
    ...
```

Правильно — сначала зависимость, потом использующая её функция.

Дважды за сессию запнулся: `require_admin` до `get_current_user` и
`check_docs_selftest` до `main`. Ловится прогоном импорта модуля.
