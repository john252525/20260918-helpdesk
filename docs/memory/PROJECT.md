# Helpdesk — API-first, единый инбокс

## Что это

Сервис технической поддержки: обращения клиентов из **WhatsApp**, **сообщений группы VK** и **Email** собираются в одно окно. Оператор отвечает прямо в переписке, видно кто и когда ответил, считаются метрики поддержки.

Ключевое архитектурное решение: **API-first**. Бэкенд ничего не знает о фронтенде. Интерфейс — всего лишь один из клиентов, наравне с мобильным приложением или ботом.

## Для кого

Мультитенантная система: платформа обслуживает несколько компаний-клиентов.

```
superadmin (владелец платформы)
```
      └── admin компании      → создаёт сотрудников, подключает свои каналы
            └── agent          → только отвечает клиентам

Данные компаний изолированы полностью: админ одной не видит ни диалогов, ни каналов, ни сотрудников другой.

## Стек

| Слой | Технология |
|---|---|
| Бэкенд | FastAPI, SQLAlchemy 2.0 (Mapped-стиль) |
| БД | PostgreSQL 16 в отдельном Docker-контейнере |
| Фронтенд | Vanilla JS SPA, без сборки |
| Авторизация | JWT (HS256), пароли через bcrypt |
| Фоновые задачи | Потоки Python (Long Poll для VK) |

## Архитектура

```
WhatsApp ─ webhook ─┐
VK        ─ Long Poll┼─► ingest ─► Conversation + Message ─► API ─► UI
Email     ─ IMAP    ─┘
```
**Входящее.** Каждый канал приводит сообщение к общему виду: `Contact` + `Conversation` + `Message`. Активный диалог переиспользуется, закрытый переоткрывается с ростом `reopen_count`.

**Исходящее.** Сообщение сохраняется в БД **всегда**, даже если провайдер недоступен — тогда `status=failed` и причина в `error`. История не теряется.

**Метрики.** Кэшируются в `Conversation` при каждом сообщении: `first_response_seconds`, `last_response_seconds`, `closed_at`. Считаются быстро, без агрегаций на лету.

## Внешние интеграции

**VK.** Работает через **Bots Long Poll**: при подключении канала бэкенд сам включает приём через `groups.setLongPollSettings`. Курсор `ts` сохраняется в базе, поэтому сообщения за время простоя не теряются. Callback API поддерживается в коде, но не используется — см. DECISIONS.

Подключить группу можно двумя способами: вручную (ID группы + ключ, созданный в настройках группы) или через **VK OAuth** — поле со ссылкой на группу и кнопка рядом с формой. VK по OAuth выдаёт community-токен группы, поэтому ручной ключ не нужен. Оба пути сходятся в `backend/app/services/vk_connect.py`, поэтому дальше источник токена никого не интересует. Подробности — в DECISIONS, ADR-022.

**WhatsApp.** Номерной провайдер: входящие вебхуком, исходящие через `sendMessage`. Нормализатор терпим к трём форматам полезной нагрузки.

**Email.** SMTP для исходящих с тредированием через `In-Reply-To`, IMAP-поллер для входящих.

**WhatsApp.** Тип канала `whatsapp` мультипровайдерный: `config.provider` выбирает вендора (пакет `backend/app/channels/whatsapp/`). Первый вендор — Touch-API: визард подключения (поиск аккаунтов по токену, создание, QR-вход), обычные вебхуки. Второй — `custom`, прежняя форма URL+токен, он же фолбэк для каналов без провайдера. Исходящие адресуются по вендорскому `thread`, ответы с телефона попадают в переписку. Управление сессией (статусы, рестарт, сброс) вынесено в визард; длительные операции идут фоном (ADR-025).
