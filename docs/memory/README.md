# Слой памяти проекта

Короткая справка, что где лежит. Полное описание методологии — в `MEMORY.md` в корне проекта.

## Три горизонта

**Холодная память** — меняется редко, читается всегда:

- `PROJECT.md` — что за продукт, стек, архитектура
- `DECISIONS.md` — ADR: почему сделали так, а не иначе
- `CONVENTIONS.md` — как писать код в этом проекте
- `GLOSSARY.md` — доменные термины

**Тёплая память** — обновляется каждую итерацию:

- `STATE.md` — где мы сейчас: сделано, в работе, дальше, блокеры
- `BACKLOG.md` — что отложено и почему

**Горячая память** — только дописывается:

- `iterations/` — журнал по одной записи на итерацию

## Один источник правды

Вопрос «где мы сейчас» имеет ответ **только в `STATE.md`**. Не дублировать в `PROJECT.md` — он про то, как устроено, а не про то, на каком мы этапе.

Вопрос «как должно быть» — это спека, ей здесь не место. Если появится отдельное ТЗ, оно живёт в `docs/spec/`.

## Что читать под задачу

| Задача | Файлы |
|---|---|
| Разобраться в проекте с нуля | `PROJECT.md` → `GLOSSARY.md` |
| Продолжить начатую работу | `STATE.md` → последние итерации |
| Написать код | `CONVENTIONS.md` → `DECISIONS.md` |
| Понять, почему сделано именно так | `DECISIONS.md` |
| Взять задачу из отложенных | `BACKLOG.md` |
| Разобраться в термине | `GLOSSARY.md` |
| Проверить историю решения | `iterations/` (по дате в имени) |

## Как обновлять

Шаги в конце итерации описаны в `AGENTS.md`. Коротко: обновить `STATE.md`, создать файл в `iterations/`, при необходимости дописать в `DECISIONS.md` и `BACKLOG.md`.

## Ссылки на код

В файлах итераций указывать конкретные файлы и функции — это ускоряет навигацию после обнуления контекста. Не «добавил изоляцию», а «`backend/app/routers/conversations.py`, хелпер `_scoped_conversation`».
