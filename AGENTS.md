# Agent instructions

Точка входа для агента. Прочитай это первым делом, затем — файлы в указанном порядке.

## Перед началом работы

Установи git-хуки, если их нет:

    ./.venv/bin/python scripts/install_hooks.py

Проверка: `ls .git/hooks/pre-commit`. Хук запускает проверки автоматически
при каждом коммите. Правила обхода — в `docs/memory/CONVENTIONS.md`.

## Порядок чтения при старте

1. `docs/memory/PROJECT.md` — что за продукт, стек, архитектура
2. `docs/memory/STATE.md` — где мы сейчас, что делается
3. `docs/memory/CONVENTIONS.md` — как писать код в этом проекте
4. `docs/memory/BACKLOG.md` — что сознательно отложено, не «чини» это
5. последние 2–3 файла из `docs/memory/iterations/`

Справочные, читай по необходимости:
- `docs/memory/DECISIONS.md` — почему сделано так, а не иначе
- `docs/memory/GLOSSARY.md` — доменные термины

## Жёсткие правила проекта

**Проверяй ПЕРЕД перезапуском сервиса, а не после.** Два быстрых прогона ловят почти всё:

```
./.venv/bin/python -c "from backend.app.main import app"
node --check frontend/app.js
```
Они находят ошибки импорта и синтаксиса за секунду. За сессию 2026-09-18..21 семь поломок сервиса случились именно из-за того, что проверка шла после.

**Не пиши в живые каналы из тестов.** Отправка уходит настоящему клиенту и отозвать её не всегда возможно. Для проверки логики ответа используй `?dry_run=true` на `POST /conversations/{id}/messages`.

**Изоляция компаний — критично.** Любой запрос к `conversations`, `contacts`, `channels`, `metrics` обязан фильтроваться по `workspace_id`. Пропущенный `WHERE` означает, что один клиент увидит переписку другого. Чужие данные отдают `404`, не `403`.

**Никаких реальных ID в примерах и плейсхолдерах.** Они попадают в UI и логи, а это утечка.

## После завершения итерации

1. Прогнать проверки:
   - `./.venv/bin/python scripts/check_docs.py` — слой памяти
   - `./.venv/bin/python -c "from backend.app.main import app"` — импорт бэкенда
   - `node --check frontend/app.js` — фронтенд
   - smoke-тест основных ручек
2. Обновить `docs/memory/STATE.md` — Done / In progress / Next / Blockers
3. Создать `docs/memory/iterations/YYYY-MM-DD-NNN-<slug>.md` по шаблону ниже
4. Архитектурное решение — дописать в `docs/memory/DECISIONS.md`
5. Новый техдолг или TODO — в `docs/memory/BACKLOG.md`
6. `git add -A && git commit` — хук прогонит проверки перед коммитом

## Шаблон файла итерации

```
# Итерация NNN — <название>
Дата: YYYY-MM-DD

## Цель
## Что сделано
- файл: что изменено
## Проверено
- как именно проверялось
## Заметки / дальше
```
